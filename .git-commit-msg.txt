fix(logs): 控制台+文件默认都输出，输出量只由 LogLevel 决定；补对拍结论

用户指出：控制台与文件日志应当默认都输出，「输出多少」交给日志等级判断。

- Config.LogPath 默认 "" -> "Log"（按 DH 约定），LogConsole 本就默认 true。
  于是「要不要输出」只看 LogLevel，「输出到哪」只看 LogPath / LogConsole，
  两个维度彻底分开。只想留控制台仍可写 LogPath = ""。
- 同步更新配置模板注释与 init 文档（不再说「默认只控制台」）。

文档（docs/决策记录.md 增补八）：
- zgrpc 服务端：延迟 flush（3 次 write -> 批量 1 次）、流对象复用、
  HPACK 静态表哈希查找、状态码快路径；单请求 CPU 9.06us -> 8.75us。
- 「连接越多反而更慢」的根因是压测器 ghz 到顶，不是服务端：
  用自带 Zig 客户端扫连接数，zgrpc 11322 -> 69448 QPS（6.1x）单调上升；
  同客户端同参数下各档位领先 grpc-go 51%~108%。
- 记录 conns=64 c=64 这类过载档两端 CPU/req 都会涨到 ~110us，
  不适合作实现优劣的依据。
- 记录测量协议与踩坑（每档 N 必须按延迟/吞吐 bound 区分，否则看起来像卡死）。
