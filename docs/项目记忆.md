## web-mvc.md

# zzig Web MVC（2026-11-12 新增）

- 入口：`zzig.web`（`src/http/{value,router,controller,view,static_files,web}.zig`）；文档 `docs/web_mvc.md`；示例 `zig build web-demo`（`examples/web/**`）。
- 约定：`Views/{Controller}/{Action}.cshtml`、`Areas/{Area}/Views/...`、`wwwroot` / `Areas/{Area}/wwwroot`（URL 前缀 = 区域名小写）。
- 处理顺序：路由优先 → 静态资源兜底 → 404；SPA 回退只对「无扩展名」路径生效。
- 视图模型必须用 `value.ObjectBuilder.init(c.arena)`（字段名/数组复制进 arena）；`ofObject(&局部数组)` 会悬垂。
- 组件式调用：`@await Component.InvokeAsync("Name", 参数)` / `@Component("Name", 参数)`；注册 `app.registerComponent`；
  视图约定 `Views/Shared/Components/{Name}/Default.cshtml`（区域内优先 `Areas/{Area}/Views/Shared/Components/...`）。
- 静态资源：`Options.wwwroot` 可改默认目录；`Options.static_roots` / `app.addStaticRoot(prefix, dir)` 加额外根
  （绝对路径可用，最长前缀优先，每根可覆盖 max_bytes/stream_threshold/cache_control）。
- 磁盘静态文件**默认全流式**（`stream_threshold = 0`）：每请求恒定 40 KB 缓冲，不整读；
  Linux 走 `Writer.sendFile`（内核 sendfile 零拷贝），Windows 回退 32 KB 读-写循环。
  想让小文件一次 read 可把阈值调高（如 64 KB）。
- 扩展名策略（对齐 ASP.NET `ServeUnknownFileTypes=false`）：未知扩展名/无扩展名默认 404；
  `statics.setMimeType(ext, ct)` 只放开指定格式，`serveUnknownFileTypes(true)` 全放开，
  `RootOptions.serve_unknown_types` 按根覆盖（下载目录放开、主站严格）。嵌入资源不受限。
- 大文件走 `Response.file` → `server.Reply.file` → `respondStreaming`；**HEAD 分支只能 `bw.flush()`，
  绝不能 `end()`**（eliding 不递减 content-length，会命中 `assert(len == 0)` panic）。
- `view.compile()` 会把源码复制进模板 arena（AST 持切片）；模板缓存按 mtime+长度失效，旧模板到 deinit 才释放。
- 测试须登记到 `src/zzig.zig` 末尾 `test { _ = @import("http/...zig"); }`，否则 `zig build test` 不收集。
- Zig 0.17.1：`trimStart/trimEnd`、`std.Io.Mutex`（配 `self.io`）、`@typeInfo(fn).param_types`。


## zgrpc-reflection.md

# zgrpc 服务反射（2026-11-13 实现）

- 三层：`src/proto.zig`（proto3 子集解析）→ `src/descriptor.zig`（→ FileDescriptorProto）→ `src/reflection.zig`（ServerReflectionInfo 双向流）。
- 路由：`refl.streamRoute()` / `streamRouteV1Alpha()`，走 **per-route `ctx`**（`route.ctx orelse server.outer_ctx`），不抢业务 ctx。
- 数据用内部 `ArenaAllocator` 长期持有，`deinit` 只需 `arena.deinit()`（逐个 free 会漏中间串）。
- **`FieldDescriptorProto.type` 必须与 `type_name` 指向的定义一致**：enum→14、message→11。写错 → grpcurl 报 `resolved "X", but it is not an message`。
- 验证：`grpcurl -plaintext HOST list / describe Svc / describe Msg / -d JSON 调用`；测试 64/64。

## 回归脚本（Windows 实测坑）
- `Stop-Process -Force` 会留下 zombie `LISTEN`（netstat `OwningProcess=0`，几十秒不消失、无法 kill）→ 固定端口会让下一次回归全 SKIP，必须**每段随机空闲端口**。
- `Get-NetTCPConnection -LocalPort X` 会连 `TIME_WAIT` 一起返回 → 必须加 `-State Listen`。
- PS 5.1 调原生 exe 会**吞掉内层双引号**：`-d '{"a":1}'` → `{a:1}`。改 `-d '@'` 从 stdin 喂 JSON。
- here-string `@'...'@` 的换行是 LF，目标文件是 CRLF 时 `String.Replace` 静默不匹配；按行改文件要核对数组切片边界（PS 切片含两端）。

## 0.17.1 同步原语（实测确认，2026-11-13）
- `std.Thread` **只剩**：`spawn/join/detach/yield/getCurrentId/getCpuCount/setName/getName`。
- `std.Thread.Mutex` / `Condition` / `RwLock` / `Semaphore` / `WaitGroup` **全部删除**，迁移到 `std.Io.Mutex` / `std.Io.Condition`。
- `std.Io.Mutex` 可独立用（`mutex: std.Io.Mutex = .init`），`lock/unlock` 不传 io。
- `std.Io.Condition.wait/waitTimeout` **必须传 `io` 且返回 cancelable 错误联合**；没有 `std.Thread.Condition` 那种无 io 版本。
- 测试里拿 io：`std.testing.io`；跨线程全局：`std.Io.Threaded.global_single_threaded.io()`。
- 结论：需要阻塞式等待的池/队列，要么传 `Io`（API 带 io 参数），要么用原子 + `compat.sleep` 轮询。


## zzig-logging-config.md

# zzig 日志 / 配置 / 线程池（2026-11-13）

- 日志配置：`Logger.init(io, gpa, "Config/logger.toml")`；加载后**自动**启热加载线程（默认 1000ms，线程名 `T`），`shutdown()` 先停线程再关配置源。
- 配置自愈：缺键 / 无注释 / 多余键 → 备份 `<path>.old` 后用实际生效值 + 完整注释原子重写，多余键**直接清理**。`reloadIfChanged` 同样自愈。
- 模板单一来源：`config_template_layout` 编译期渲染成 `default_config_template`；**不要写死默认值**（曾出现 8192 vs 65536 漂移）。
- 文件 sink 并发：`useFile/closeFile/emitText/emitBatch/fileEnabled` 全走 `file_mutex`；换 sink = 先建新 → 锁内换指针 → 解锁后释放旧。
- 坑：`loadConfigFile` 曾 `errdefer file.deinit()` + catch 里手写 `deinit()` 双释放 → 配置出错时段错误。
- 线程池 `src/threading/pool.zig`：`Io.Mutex` + `Io.Condition.waitTimeout` + `Io.Event`，零轮询；`create/destroy` 堆指针模型；弹性 `min/max/idle_timeout_ms`。
- 池的取舍：短任务走池（省 ~93.7us/连接）；长连接/流式用独立线程 + `markAsLongTask()`（日志 Kind=N / Name=L）。
- zgrpc 接入：`Server.dispatch = .pool` + `Server.pool`，`acceptLoop` 统一入口，提交失败回退独立线程。
