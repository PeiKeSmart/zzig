# zzig 决策记录

## 2026-11-11 接收 Pek.ZCode 下沉的通用件

- **用户原话**：「同样的也是要尽可能的提取到zzig复用公共方法」
  （上下文：`G:\Code\Zig\Pek.ZCode` 基于 C# `DH.NCode` / Rust `Pek.RCode` 落地 Zig ORM 后，
  要求把与业务无关、可复用的能力提到 zzig，避免各仓库各写一份）。
- **检索证据（先查后写）**：zzig 内 `Decimal` / `DateTime` / `sqlite` 关键词**零命中**；
  `File` 仅有 `CurrentPath`/`CurrentPathZ`；无字符串缓冲类型。→ 不存在重复实现。
  `http` 模块已在用 `std.Io.Writer.Allocating` → `Buf` 用同一 API 不额外抬高版本门槛。
- **新增模块**（全部通用、零业务依赖）：

  | 模块 | 位置 | 对外名 |
  |---|---|---|
  | 字符串缓冲 | `src/text/buf.zig` | `zzig.Buf` |
  | 十进制（尾数+缩放因子） | `src/number/decimal.zig` | `zzig.Decimal` |
  | 日期时间（无时区，7 位小数秒文本） | `src/time/datetime.zig` | `zzig.DateTime` |
  | 数据库值模型 | `src/db/value.zig` | `zzig.db.Value` |
  | SQLite 驱动（动态加载 DLL） | `src/db/sqlite.zig` | `zzig.db.sqlite` / `zzig.sqlite` |
  | 文件工具（唯一临时名 / 静默删除） | `src/file/file.zig` | `zzig.File.UniqueTempName` / `DeleteQuiet` |

- **API 约定**：与仓库既有风格一致（`Strings`/`File` 用 PascalCase 函数名）；类型用名词（`Decimal`/`DateTime`/`Value`/`Buf`）。
  `zzig.db` 为分组命名空间，`zzig.sqlite` 是 `zzig.db.sqlite` 的便捷别名。
- **平台说明**：`zzig.sqlite` 用 Win32 `LoadLibraryA`/`GetProcAddress` 动态加载（Zig 0.17 的 `std.DynLib` 不支持 Windows），
  非 Windows 平台返回 `null`（驱动不可用）。`File.DeleteQuiet` 同理仅在 Windows 生效，其它平台静默跳过。
  两处均已在源码注释与 `docs` 中写明。
- **验证（实际输出）**：`zig build test --summary all` → `Build Summary: 5/5 steps succeeded; **51/51 tests passed**`
  （24 项主测试 + 27 项 XML 测试；本次新增 8 项：Decimal×2、DateTime×3、Buf×1、db.Value×1、sqlite 驱动×1、File×1）。
- **后续纪律**：这些能力**只在 zzig 修改**；消费方（首个是 `Pek.ZCode`）一律 import，不再复制实现。
  新增通用件的门槛：不依赖任何业务仓库、有独立单测、有清晰的生命周期/平台说明。

## 2026-11-11 增补：文件读写工具

- **用户原话**：「请继续，同样也可以参考Rust搞绿色版本来测试验证。」
- **新增**：`File.ReadAllAlloc(allocator, path, max_bytes)` 与 `File.WriteAll(path, bytes)`。
- **起因**：0.17 移除了 `std.fs.cwd().readFileAlloc`；`Pek.ZCode` 读 `Model.xml`、
  `zcodegen` 落盘实体都需要跨版本写法，属于通用能力，放公共库。
- **实测坑**：`compat.File.readAll` 在读到 EOF 时会抛 `EndOfStream`（不是返回 0），
  分块循环会误判；改用 `getEndPos` + `readToEndAlloc`，超限显式报 `error.FileTooBig`。
- **验证**：`zig build test` **52/52 全通过**（新增 File 读写往返 1 项）。

## 2026-11-11 增补：MySQL 绿色驱动 + 模块测试收集修复

- **用户原话**：「**MySQL 执行驱动** 不是说了参考Rust有一个绿色版本么？」——即：不加载 `libmysqlclient`，
  照 Rust `Pek.RCode/src/mysql.rs`（`mysql` crate 纯协议）一样自己做 wire protocol。
- **新增**：`db/mysql.zig`（`zzig.db.mysql`）+ `db/row.zig`（各驱动共用 `Row`，`db/sqlite.zig` 改为引用它，消除重复定义）
  + `db/mysql_loopback_test.zig`（回环假服务端端到端用例）。
- **能力**：握手 v10、`mysql_native_password` 完整、`caching_sha2_password`（仅 fast auth）、`COM_QUERY`、
  预处理二进制协议（`COM_STMT_PREPARE/EXECUTE/CLOSE`，按 `Value` 绑定参数）、`COM_PING/QUIT/INIT_DB`。
  **显式不支持**（报错不降级）：TLS、`caching_sha2` 完整鉴权（明文需 RSA）、`MULTI_STATEMENTS`、`FOUND_ROWS`、压缩、LOCAL INFILE。
- **`CLIENT_FOUND_ROWS` 口径**：不开。已核对 Rust 侧默认能力集
  （`mysql-28.0.4/src/conn/mod.rs:777 get_client_flags` 无 `FOUND_ROWS`），故 `affected_rows` = 实际变更行数，两边一致。
- **Zig 0.17 实测坑（新增到「0.17 差异」清单）**：
  1. **`**` 数组重复运算符已移除**：`[_]u8{0} ** 20` 报 `binary operator '*' has whitespace on one side`；
     改用 `@splat(0)`（或 `std.mem.zeroes([N]T)`）。
  2. **`Stream.read()` 不可用**：std 内部 `const rc, _ = try (try io.operate(...)).net_read;` 会报
     `type 'Io.net.Stream.ReadResult' cannot be destructured`。改为直接 `io.operate(.{ .net_read = .{ .socket_handle, .data } })`
     取 `res.data_len`；写同理走 `.net_write`（`Stream` 没有裸 `write`，只有 `writer` 接口）。
  3. **模块内的 test 块默认不执行**：`zig test` 只收集「同一模块内、根文件**直接 import**」的文件的 test 块；
     跨模块 `@import("zzig")` 与 `std.testing.refAllDecls` 都**不会**收集（0.17 已无 `refAllDeclsRecursive`）。
     这就解释了为什么 `db/sqlite.zig` 的用例从没跑过 —— 之前报的 52 项其实是 `test.zig`(25) + `xml-tests`(27)。
  4. 修法：`build.zig` 增加以 `src/zzig.zig` 为根的 `zzig-module-tests`，并在 `src/zzig.zig` 里
     `test { _ = @import("db/mysql.zig"); … }`。修正后 **52 → 79 项**（module-tests 27），退出码 0。
- **验证（实测）**：
  - 固定字节单测：握手、两种鉴权散列（含独立算法重算比对）、OK/ERR、文本行、二进制行（NULL 位图）、
    二进制日期时间 4/7/11 字节、lenenc 边界、列定义；
  - 回环端到端：真 TCP 上跑完握手 → 鉴权（服务端按算法重算摘要并逐字节比对）→ `COM_QUERY` → 结果集 → PING → QUIT；
  - `zig build test --summary all` → `7/7 steps succeeded; 79/79 tests passed`。
- **未做**：TLS、`caching_sha2` 完整鉴权、预处理语句缓存（Rust 默认 256 条，本实现每次 prepare/close —— 语义一致，仅多一次往返）、
  真库验证（本机无 MySQL 服务，需 `Pek.ZCode` 侧 `-Dmysql-conn`）。

## 2026-11-11 增补（二）：按 C# 绿色版 `DH.MySql` 校口径，补齐差异

- **用户原话**：「**Mysql绿色版文件你没有找到吗？**」——指的是 `G:\Code\Pek.FrameWork\DH.MySql`
  （NewLife 自实现协议的 MySQL 驱动，无第三方依赖），前一版我误以为「绿色版」只是 Rust `mysql` crate 的纯协议写法。
- **逐项对照结果**（源码位置已核对）：

  | 口径 | `DH.MySql`（权威） | 我上一版 | 处理 |
  |---|---|---|---|
  | `CLIENT_FOUND_ROWS` | **开启**（`Authentication.cs` `// UseAffectedRows`） | 关闭（对齐 Rust crate） | **改为开启** → `affected_rows` = 匹配行数 |
  | `MULTI_STATEMENTS` / `MULTI_RESULTS` / `PS_MULTI_RESULTS` | 开启 | 关闭 | **改为开启**（多结果集由 `drainMoreResults` 读掉） |
  | `caching_sha2_password` 完整鉴权 | **实现**（`PerformFullAuthenticationAsync`：请求公钥 → RSA 加密） | 只做 fast auth，其余报错 | **补齐 RSA**（新增 `crypto/rsa.zig`） |
  | BIT 值字节序 | **小端**（`ConvertBitBytesToUInt64`：`value \|= byte << (i*8)`） | 大端（Rust `Pek.RCode` 口径） | **改为小端**；注意该分支 `DH.MySql` **无单测**，待真库确认 |
  | 连接串键名 | `Server` / `Port` / `Database` / `UserID` / `Password` | 少了 `UserID` | `Pek.ZCode` 的 `dal` 已补 `UserID`/`UserId` |

- **新增 `src/crypto/rsa.zig`**：PEM/DER 解析（SubjectPublicKeyInfo）+ `RSAES-OAEP(SHA1, 空 label)` + 平方-乘模幂。
  只做加密（不需要私钥运算）。随机种子的来源：0.17 的 `std.crypto.random` 已移除，改用 `Io.random(io, buf)`。
- **实测坑（新增到「0.17 差异」）**：
  1. `Managed.toString(self, allocator, base, case)` 是 **4 个参数**（多了 `std.fmt.Case`）；
     `std.fmt.bytesToHex` 的返回类型是 `[input.len*2]u8`，**长度必须 comptime 已知**（不能传运行时切片）。
  2. **借用复用包缓冲会变成垃圾**：`parseHandshake` 返回的 `auth_plugin_name` 指向 `self.pkt`，
     鉴权往返里下一次 `readPacket` 就把它覆盖成乱码（表现为「插件名不匹配」）。握手时**必须拷贝**到自己缓冲。
  3. 回环假服务端固件里漏了 `RSAPublicKey ::= SEQUENCE` 那层，现象是 BIT STRING 内容直接以 `0x02` 开头 → `DerFormat`。
- **验证**：
  - `crypto/rsa.zig` 单测 3 项：DER/PEM 解析（48 字节模长 + `e=65537`）、模幂已知值（`4^13 mod 497 = 445`）、OAEP 编码可逆；
  - 回环端到端新增 2 项：① 假服务端对 `caching_sha2` 初始摘要按算法重算并逐字节比对 → 要求完整鉴权 →
    返回 PEM 公钥 → 校验客户端发来的密文长度 = 48 且非全 0 → OK；② 固件自检（DER/PEM 可被驱动解析）；
  - `zig build test --summary all` → `7/7 steps succeeded; **84/84** tests passed`（module-tests 32）。
- **仍未做**：TLS（`CLIENT_SSL` 不发）、压缩协议、LOCAL INFILE、预处理语句缓存、真库验证。

## 2026-11-11 增补（三）：真库验证（本机免安装 MySQL 8.0.29）→ 三处实测修正

- **用户原话**：「那你可以直接下载绿色版本到本地项目并持久保存用于后续测试」。
  本机已有免安装版（`G:\Tools\mysql-portable\mysql-8.0.29-winx64` 与 `E:\Soft\mysql-dist\mysql-8.0.28-winx64`），
  无需再下载；由 `Pek.ZCode/tools/mysql-local.ps1` 在项目内起独立实例（端口 3307、数据目录 `.tools\mysql\data-3307`，
  重启后仍在），并建好 `zcode_test` 库与 `zcode_native` / `zcode_sha2` 两个测试账号。
- **实测修正 1：BLOB/TEXT 靠 charset 区分**。协议里 TEXT 与 BLOB 共用类型码（252 等），
  只看类型会把 TEXT 列读成 Blob（真库现象：`Title` 变成 `[blob 12 字节]`）。
  按 `charset == 63` 判二进制，与 `DH.MySql/MySqlColumn.RemapTypeByCharset` 同口径。
- **实测修正 2：`caching_sha2_password` 完整鉴权的填充是 PKCS#1 v1.5，不是 OAEP**。
  OAEP 实现本身正确（产物能被 openssl `pkeyutl -decrypt -pkeyopt rsa_padding_mode:oaep -pkeyopt rsa_oaep_md:sha1`
  解出原文），但服务端回 `1045 Access denied`；改用 `RSAES-PKCS1-v1_5` 后同一账号立即登入成功。
  载荷 = `RSA_encrypt( (password + '\0') XOR 握手 nonce )`（与 C# `GetXor` 一致；`AuthSwitch` 里那个 nonce 不用于 full auth）。
  OAEP 实现保留（已单测），后续遇到只认 OAEP 的服务端可切回。
- **实测修正 3：BIT 列字节序是「大端」**。真实服务器上 `BIT(16)` 存 `0x0102`，文本协议读回字节为 `[0x01,0x02]`；
  按大端还原得 **258**（正确），按小端得 513（错）。
  即 **C# 绿色版 `DH.MySql.ConvertBitBytesToUInt64` 的小端实现是错的**，Rust `Pek.RCode` 的大端与实测一致。
  已改回大端，并由 `Pek.ZCode` 的真库用例（`MySQL 真库：BIT 列字节序`）锁定断言。
- **另一个真 bug（非口径）**：`parseHandshake` 与 `AuthSwitchRequest` 返回的插件名/切片都**借用复用包缓冲**，
  下一次 `readPacket` 即被覆盖（表现为「插件名变成乱码」）。两处都已改成拷贝到本地缓冲。
- **验证**：zzig `7/7 steps succeeded; 84/84 tests passed`；
  `Pek.ZCode` 真库（root / native）`12/12 tests passed`、真库（zcode_sha2 / 完整鉴权）`11/11 → 12/12 tests passed`，退出码 0。
