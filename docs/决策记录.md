## 2026-11-11 接收 Pek.ZCode 下沉的通用件

- **用户原话**：「同样的也是要尽可能的提取到zzig复用公共方法」
  （上下文：`G:\Code\Zig\Pek.ZCode` 基于 C# `DH.NCode` / Rust `Pek.RCode` 落地 Zig ORM 后，
  要求把与业务无关、可复用的能力提到 zzig，避免各仓库各写一份）。
- **检索证据（先查后写）**：zzig 内 `Decimal` / `DateTime` / `sqlite` 关键词**零命中**；
  `File` 仅有 `CurrentPath`/`CurrentPathZ`；无字符串缓冲类型。→ 不存在重复实现。
  `http` 模块已在用 `std.Io.Writer.Allocating` → `Buf` 用同一 API 不额外抬高版本门槛。
- **新增模块**（全部通用、零业务依赖）：

  | 模块 | 位置 | 对外名 |
  |---|---|---|
  | 字符串缓冲 | `src/text/buf.zig` | `zzig.Buf` |
  | 十进制（尾数+缩放因子） | `src/number/decimal.zig` | `zzig.Decimal` |
  | 日期时间（无时区，7 位小数秒文本） | `src/time/datetime.zig` | `zzig.DateTime` |
  | 数据库值模型 | `src/db/value.zig` | `zzig.db.Value` |
  | SQLite 驱动（动态加载 DLL） | `src/db/sqlite.zig` | `zzig.db.sqlite` / `zzig.sqlite` |
  | 文件工具（唯一临时名 / 静默删除） | `src/file/file.zig` | `zzig.File.UniqueTempName` / `DeleteQuiet` |

- **API 约定**：与仓库既有风格一致（`Strings`/`File` 用 PascalCase 函数名）；类型用名词（`Decimal`/`DateTime`/`Value`/`Buf`）。
  `zzig.db` 为分组命名空间，`zzig.sqlite` 是 `zzig.db.sqlite` 的便捷别名。
- **平台说明**：`zzig.sqlite` 用 Win32 `LoadLibraryA`/`GetProcAddress` 动态加载（Zig 0.17 的 `std.DynLib` 不支持 Windows），
  非 Windows 平台返回 `null`（驱动不可用）。`File.DeleteQuiet` 同理仅在 Windows 生效，其它平台静默跳过。
  两处均已在源码注释与 `docs` 中写明。
- **验证（实际输出）**：`zig build test --summary all` → `Build Summary: 5/5 steps succeeded; **51/51 tests passed**`
  （24 项主测试 + 27 项 XML 测试；本次新增 8 项：Decimal×2、DateTime×3、Buf×1、db.Value×1、sqlite 驱动×1、File×1）。
- **后续纪律**：这些能力**只在 zzig 修改**；消费方（首个是 `Pek.ZCode`）一律 import，不再复制实现。
  新增通用件的门槛：不依赖任何业务仓库、有独立单测、有清晰的生命周期/平台说明。

## 2026-11-12：Web MVC 一体化（Controller / 视图 / 区域 / wwwroot）

- **用户原话**：「zzig这个项目帮我参考C#和DH.RustBase实现web的Controller和视图以及区域还有wwwroot静态资源这一套方案」。
- **复用检索（先查后写）**：
  - `Get-ChildItem 'E:\Code\Rust\DH.RustBase\src\net'` → 命中 `router.rs`(15.8KB) / `controller.rs`(25.4KB) /
    `static_files.rs`(29.4KB) / `razor/*`(6252 行) 与 `Doc/{Razor子集模板引擎需求,SPA与MVC一体化}.md`；
  - 本仓库 `src/http/{http,server,enhanced}.zig` 只有「客户端 + 监听线程层」，无路由/控制器/视图/静态资源；

  - 结论：按 DH.RustBase 的职责划分在 `src/http/` 下新增 6 个模块，**API 面与语义对齐**，实现按 Zig 0.17.1 重写（无外部依赖）。
- **新增文件**：
  - `src/http/value.zig`：视图值模型（对象/列表/标量 + JSON 解析/序列化 + C# 口径文本化 + HTML 转义 + `ObjectBuilder`）；
  - `src/http/router.zig`：路由（`{name}` 段捕获、大小写不敏感、405+Allow、中间件洋葱链、fallback）+ 请求上下文 `Ctx`；
  - `src/http/controller.zig`：控制器（`/{prefix}/{action}`、动作名小写查表、参数绑定「路由→查询→表单→JSON」、
    `{code,message,data}` 信封、视图动作、1 参/2 参两种动作签名）；
  - `src/http/view.zig`：Razor 子集引擎（`@Model.X` / `@(expr)` / `@Raw` / `@if` / `@foreach` / `@{ var; Layout }` /
    `@RenderBody` / `@section` / `@RenderSection(Async)` / `@Html.Partial(Async)` / `@* *@` / `@@`；表达式子集含
    `??`/三元/比较/算术；子集外**编译期报错并带行列号**）+ 视图解析（`Views/{Controller}/{Action}.cshtml`、
    `Areas/{Area}/Views/...`、`Views/{Area}/...`、`Shared`、回退区域、显式 `/` 与相对片段）+ 布局链 + 分区 + 模板缓存；
  - `src/http/static_files.zig`：`wwwroot` 静态资源（MIME、默认文档、目录穿越防护、弱/强 ETag + 304、
    区域多根最长前缀优先、嵌入资源、SPA 回退 + 排除前缀）；
  - `src/http/web.zig`：`App` 装配（路由优先 → 静态兜底 → 404；区域注册 `addArea`；桥接 `http_server`）。
  - 示例 `examples/web_mvc_example.zig` + `examples/web/**`（Views / Areas / wwwroot），`zig build web-demo` 一键跑；
    文档 `docs/web_mvc.md`。
- **关键决策**：
  1. **控制器/中间件用「函数指针 + 上下文指针」**（Zig 无闭包捕获），以便跨线程共享且零分配；
     `Controller.map/get/...` 用 `comptime func: anytype` + `toActionFn` 同时支持 `fn(c)` 与 `fn(self, c)`；
  2. **静态资源挂路由之后**（与 DH.RustBase「StaticFiles 挂 fallback」一致），SPA 回退只在静态层且**只回退无扩展名路径**
     （避免缺失的 `.js/.css` 变成 HTML）；
  3. **视图缓存按「mtime + 长度」失效**，命中零读盘；旧模板只在 `ViewRenderer.deinit` 释放（不做引用计数，
     热改期短时可接受，已在文档标注）；
  4. **`server.Reply` 新增 `headers` 字段**：否则 `Location`/`ETag`/`Allow` 在桥接层被丢弃（302、304、405 就是坏的）；
  5. 文本化对齐 C#：`bool` → `True`/`False`、`null` → 空串、整数无小数；HTML 转义只处理 `& < > " '`
     （不追求 `HtmlEncoder.Default` 的全字符探测口径——那是 DH.RustBase 的 C# 互操作需求，本项目无此约束）。
- **踩坑与修正（实测）**：
  1. **编译期源码悬垂**：AST 里的文本/标识符切片指向源缓冲区，`loadTemplate` 编译后 `free(source)` → 渲染期读到垃圾

  2. **页面模型的栈悬垂**：动作里 `ofObject(&局部数组)` 返回后栈帧失效（现象：`<li></li><li></li><li>0.000…2</li>`）。

  3. Zig 0.17.1 API：`std.mem.trimLeft/trimRight` 已改名 `trimStart/trimEnd`；`std.Thread.Mutex` 已移除，
     改用 `std.Io.Mutex`（`lockUncancelable(io)` / `unlock(io)`）；`@typeInfo(Fn).params` → `param_types`；
     格式化字符串里的 `@{...}` 必须转义成 `@{{...}}`；union 字段类型不能直接写 `Node.render_section`（改用命名结构 `SectionCall`）；
  4. 模板里出现字面量 Razor 示例（如文档页面写 `@if`）必须写 `@@if`，否则被当代码解析（示例 About/Index 已修正）。
- **验证（实测）**：

## 2026-11-12 增补：静态目录可配置 + 额外静态根 + 大文件流式

- **用户原话**：「另外要有个功能可以在wwwroot这个默认静态目录地址外，还可以改这个目录路径以及额外中静态目录路径，

- **已支持/新增**：
  - **改默认目录**：`App.Options.wwwroot = "assets/public"`（或 `null` 关闭静态资源），原本已支持，本轮补文档与示例；
  - **额外静态根**：`Options.static_roots`（`[]const static_files.RootOptions`）、`App.addStaticRoot(prefix, dir)`、
    `App.addStaticRootOptions(...)`；`url_prefix` 为空串=站点根，最长前缀优先，不同根互不可见；
  - **每根可覆盖**：`max_bytes`（单文件上限，默认 1 GB）、`stream_threshold`（默认 4 MB）、`cache_control`；
    全局 `setMaxBytes` / `setStreamThreshold` / `setCacheControl` 仍在；
  - **绝对路径**：`dir` 支持 `D:\downloads` 这类绝对路径（与相对项目目录的路径同一套处理）。
- **大文件下载（关键补齐）**：原实现把静态文件整读进内存（上限 32 MB），挂下载目录会直接失败。
  本轮新增文件流式响应链路：`router.Response.file` → `server.Reply.file` → `req.respondStreaming`
  + `content-length` 分块发送（32 KB 读缓冲），句柄由服务端关闭；`HEAD` 只发头且 `content-length` 准确。
- **踩坑（实测 panic，务必记住）**：`BodyWriter` 的 **eliding（HEAD）分支不递减 content-length 状态**，
  HEAD 里调用 `bw.end()` 会命中 `assert(len == 0)` 直接 panic（现象：GET 正常、随后 `curl -I` 把进程打死）。
  修法：HEAD 分支只 `bw.flush()`，不调 `end()`；并补「GET + HEAD 双请求」真 socket 用例锁住该行为。
- **验证（实测）**：
  - `zig build test --summary all` → **7/7 steps succeeded；exit 0**（模块测试 116/116：新增额外根、根级
    max_bytes/cache_control、流式阈值、Web 层多根桥接、服务端 GET+HEAD 流式）；
  - `zig build` → exit 0；
  - 端到端：`/downloads/readme.txt` 200（额外根）；`/app.css`（默认目录已改为 `examples/web/wwwroot`）200；
    `/downloads/a.txt` 404；`--path-as-is /downloads/../app.css` 404（穿越被拒）；
    **6 MB 文件 GET → 200 / 6291456 字节、HEAD → content-length: 6291456**，进程无 panic。
- **未做**：`Range`（断点续传/分片下载）——当前为整文件顺序流式。

## 2026-11-12 增补：磁盘静态资源默认全流式 + Linux sendfile 零拷贝

- **用户原话**：「静态文件下载本身不经过内存的吧？」→「那要是资源文件也都经过内存的话那不是很浪费资源？」。
- **原先的问题（属实）**：只有 > 4 MB 才流式；JS/CSS/图片这类资源每次都 `readFileAlloc` 整读进请求 arena，
  内存占用 = 并发请求数 × 资源大小，确实浪费。
- **改动**：
  1. `stream_threshold` 默认 **4 MB → 0**：**所有磁盘静态文件默认都不整读进内存**，每请求固定
     「8 KB 发送缓冲 + 32 KB 读缓冲」；需要「小文件一次 read」时把阈值调高（如 64 KB）即可；
  2. `server.serveOne` 文件发送**优先走 `Writer.sendFile`**：Linux（有 libc）落到内核 `sendfile`，
     **file→socket 零拷贝、不经过用户态内存**；平台返回 `Unimplemented`（如 Windows）时回退为 32 KB 读-写循环；
  3. 测试辅助 `responseBody`：磁盘文件现在返回 `Response.file`，断言改为从句柄读出来校对。
- **踩坑**：`File.Reader.interface.readSliceShort` 的 EOF 语义是「返回 0」，错误集只有 `error.ReadFailed`，
  写 `catch error.EndOfStream` 会编译失败（`EndOfStream` 不在目标错误集）。
- **验证（实测）**：
  - `zig build test --summary all` → **7/7 steps succeeded；141/141 tests passed**，exit 0；`zig build` → exit 0；
  - 端到端：`/app.css`、`/downloads/readme.txt` 200 且正文正确；HEAD → `content-length: 267`；
    6 MB 文件 GET → 200 / 6291456 字节、HEAD → `content-length: 6291456`；进程无 panic；
  - 零拷贝路径在 Windows 上走回退分支（std 的 `have_sendfile` 仅 Linux/带 libc），本轮**未在 Linux 实测**。
  （`mysql-28.0.4/src/conn/mod.rs:777 get_client_flags` 无 `FOUND_ROWS`），故 `affected_rows` = 实际变更行数，两边一致。
- **Zig 0.17 实测坑（新增到「0.17 差异」清单）**：
  1. **`**` 数组重复运算符已移除**：`[_]u8{0} ** 20` 报 `binary operator '*' has whitespace on one side`；
     改用 `@splat(0)`（或 `std.mem.zeroes([N]T)`）。
  2. **`Stream.read()` 不可用**：std 内部 `const rc, _ = try (try io.operate(...)).net_read;` 会报
     `type 'Io.net.Stream.ReadResult' cannot be destructured`。改为直接 `io.operate(.{ .net_read = .{ .socket_handle, .data } })`
     取 `res.data_len`；写同理走 `.net_write`（`Stream` 没有裸 `write`，只有 `writer` 接口）。
  3. **模块内的 test 块默认不执行**：`zig test` 只收集「同一模块内、根文件**直接 import**」的文件的 test 块；
     跨模块 `@import("zzig")` 与 `std.testing.refAllDecls` 都**不会**收集（0.17 已无 `refAllDeclsRecursive`）。

  5. `buildResponse`/`buildStaticHeaders` 增加 `extra` 头参数；**`serve` 旧签名保留**（内部传 `false`），既有测试不受影响。
